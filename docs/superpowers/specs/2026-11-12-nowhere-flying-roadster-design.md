# HAUS NOWHERE — 성수 2041 날으는 로드스터 설계 스펙

- **작성일**: 2026-11-12
- **기반**: 성수 2041 월드(`tools/nowhere/blender/future.py`, `layout.movers`, `public/src/nowhere/movers.js` · `world.js`), 2026-10-15 테슬라 로드스터 공개 시연 조사
- **목표**: 뚝섬로를 달리던 날으는 로드스터가 20초에 한 번씩 분사와 함께 떠올라 회전하는 장면을 보여 줘, 2041 거리에 놀라움을 더한다.

## 0. 확정된 결정

| 항목 | 결정 |
|---|---|
| 차 | 테슬라 로드스터(2026 공개형)를 닮은 흰 쐐기형 2인승 쿠페. 로고 · 'RDSTR' 등 상표 글자는 넣지 않는다 |
| 대수 · 동작 | 2대, 차마다 다른 동작: **A 날아가기**(이륙 → 배럴 롤 → 지붕 너머로 사라짐), **B 점프 착지**(정차 포드 2대를 뛰어넘으며 킥플립 → 착지 → 계속 주행) |

| 태블릿 예산 | 모바일 예산(그리기 180 · 삼각형 0.9 M)에 그리기 +6 · 삼각형 +20 K → **186 · 0.92 M**. 휴대폰은 지금 예산 그대로 |

## 1. 레퍼런스 요약 (2026-10-15 공개, 텍사스 스페이스X 시험장)

- 외형: 1980년대풍 길고 낮은 쐐기형 2인승 하드톱 쿠페, 흰 차체, 어두운 유리 캐노피, 검은 휠, 뒤쪽 가는 빨간 라이트 줄, 아래로 접히는 전조등, 펼쳐지는 리어 윙, 위로 열리는 문.
- 추진: 번호판 아래 냉가스 노즐 4개 + 바닥 · 옆 분사구. 흰 압축공기 분사(불꽃 없음).
- 시연: 평지 가속 → 바닥 분사로 이륙 → 차량 5대 위를 넘으며 꼭대기에서 옆 분사로 한 바퀴('킥플립') → 바닥 분사로 받쳐 바퀴로 착지. 하프파이프에서 뒤집혀 떨어지며 노즐로 돌아 착지('배럴 롤'). 공중 몇 초.
- 출처: Dezeen(2026-10-16), Electric Future(2026-10-15), Fox News, 아이뉴스24, 네이트 뉴스(2026-11-04).

## 2. 모델 (`NW_future`)

| 객체 | 내용 |
|---|---|
| `FU_roadster_a`, `FU_roadster_b` | 차체 한 메시(차체 · 캐노피 · 휠 · 라이트 줄 · 리어 윙 · 노즐을 합침). 길이 4.4 m · 폭 1.95 m · 높이 1.15 m, 앞 = 로컬 +X(이동체 규칙). 삼각형 ≤ 3,000. 재질은 기존 이동체 아틀라스 `NWF_mover` 한 장(흰 차체, 어두운 유리, 검은 휠, 빨간 줄 영역을 아틀라스에 더함) → 그리기 1 |
| `FU_roadster_a_plume`, `FU_roadster_b_plume` | 분사 기둥: 뒤 노즐 4개 + 바닥 4곳의 흰 반투명 원뿔을 한 메시로(삼각형 ≤ 400). 재질 `NWF_plume`(흰색, 투명, 그림자 없음, 깊이 쓰기 없음). 차체의 자식, 분사할 때만 보임 → 그리기 1(보일 때만) |
| `FU_parked_pod.0`, `.1` | B 가 뛰어넘는 정차 포드 2대. 기존 포드 모양 복제(인스턴스, 그리기 1). 보행 장애물로 막힌다 |

- 바퀴는 따로 돌리지 않는다(바퀴마다 그리기가 늘어난다). 휠에 회전 흐림 무늬를 그려 둔다.
- 이동체는 단일 사용자 메시 규칙을 지킨다(gltf-transform `--instance` 가 같은 메시 노드 이름을 지우므로). 정차 포드는 움직이지 않으므로 인스턴스로 합쳐도 된다.

## 3. 경로와 동작 (`layout.movers`, kind `roadster`)

- 뚝섬로 서행 바깥 차로(Blender y −37.125, three z 37.125, 동 → 서)를 쓴다. 이동 포드(`pod_w1` y −40.375, 동행 차로들)와 겹치지 않는다. 구현 중 차로가 막혀 있으면 가까운 빈 차로로 옮기고 보고한다.
- 정차 포드: 같은 차로 연석 쪽, x −30 · −36 근처(Blender). 거리 시점에서 약 70 m.
- 시간표(초기값, 구현 중 화면을 보며 조정 — 값은 `future.py` 의 표가 기준):

| 구간 | A 날아가기 (위상 0) | B 점프 착지 (위상 20 s) |
|---|---|---|
| 등장 | x +160 에서 보이기 시작, 22 m/s 로 서진 | 같음 |
| 분사 시작 | x ≈ +10(HAUS 앞) | x ≈ −18 |
| 공중 | 0.4 s 상승 뒤 1.2 s 동안 진행 방향 축 360° 배럴 롤, 계속 가속 상승하며 북서쪽 벽돌 지붕 너머로(건물 solids 와 3 m 이상) | 포물선 점프 최고 6 m(x ≈ −33), 꼭대기 ±0.5 s 동안 진행 방향 축 360° 킥플립 |
| 끝 | 고도 90 m · x −300 근처 하늘에서 사라짐(숨김) | x −48 근처 바퀴로 착지(바닥 분사 0.3 s) → 서진 계속 → x −260 에서 숨김 |
| 분사 | 이륙 ~ 롤 끝까지 전체, 이후 뒤 노즐만 서서히 줄임 | 이륙 0.4 s, 착지 0.3 s |
| 보이지 않는 시간 | 나머지(숨김 — 그리기 0) | 나머지 |

- `layout.movers` 항목: `{ id, kind: 'roadster', object, plume, period: 40, phase, keys: [{ t, pos: [x, y, z], yaw, roll, pitch, thrust }], visible: [t0, t1] }` (three 좌표). Blender 가 시간표를 키 목록으로 내보내고 웹은 보간만 한다.
- 웹 `movers.js` 에 순수 함수 `roadsterPose(def, time)` → `{ visible, pos, yaw, pitch, roll, thrust }`: 위치는 키 사이 Catmull-Rom, 각도 · 분사는 선형 + smoothstep. 롤은 누적 각도(0 → 2π)로 보간한다.
- `world.js` 이동체 갱신: 로드스터는 `roadsterPose` 로 자세를 놓고, `visible` 이 거짓이면 차체 · 분사를 숨기며, 분사 메시는 `thrust > 0.02` 일 때만 보이고 크기(길이)를 `thrust` 에 비례시킨다.

## 4. 기기 구분 (`quality.js`)

- `detectDeviceClass()` → `'desktop' | 'tablet' | 'phone'`:
  - 태블릿: iPad(UA `iPad`, 또는 `Macintosh` + `maxTouchPoints > 1`), 안드로이드 중 UA 에 `Mobile` 이 없는 것, 그 밖의 터치 기기 중 `min(screen.width, screen.height) ≥ 600`.
  - 휴대폰: 그 밖의 모바일(`Mobi` · `iPhone` · `Android … Mobile`).
- 등급은 지금처럼 태블릿 · 휴대폰 모두 `mobile`(같은 모바일 자산). `getQualityConfig` 에 `device` 와 `roadsters: device !== 'phone'` 를 더한다.
- 주소 `&tier=tablet` = 모바일 등급 + 태블릿(시험용). `&tier=mobile` 은 휴대폰으로 본다.
- 휴대폰: 로드스터 · 분사 · 정차 포드를 만들지 않거나 숨긴다(보행 장애물에서도 뺀다).

## 5. 예산 · 성능

| 등급 | 그리기 | 삼각형 | 기준 시점 |
|---|---|---|---|
| 데스크톱 | ≤ 300 (지금 최악 + 최대 5) | ≤ 2.0 M | street · future · aerial |
| 태블릿 | ≤ 186 | ≤ 0.92 M | 같음(로드스터 두 대 · 분사 · 정차 포드가 모두 보이는 최악 시각 포함) |
| 휴대폰 | ≤ 180 (지금 178 그대로) | ≤ 0.9 M (지금 898,927 그대로) | 같음 |

- FPS ≥ 60(데스크톱 · `&tier=tablet`, 전원 연결). 전송량 증가 ≤ 0.3 MB.
