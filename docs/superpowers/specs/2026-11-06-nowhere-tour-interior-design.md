- **작성일**: 2026-11-06
- **기반**: 성수 2041 · DS2 산악 월드 뷰어(`public/nowhere*.html`, `public/src/nowhere/`), 실내 에셋 `public/assets/inner/`
- **목표**: 디트로이트 감성의 '분석 모드'를 걷어내고, 인트로 비행처럼 카메라가 스스로 움직이는 **시나리오 투어**로 두 건물을 안내한다. 성수 건물(HAUS NOWHERE 타워)은 **실내 4개 층**(B1F · 1F · 12F · 13F)으로 입장할 수 있다.

## 1. 시나리오 투어 (외관)

### 1.1 흐름

```
[시작] 페이지 로드(URL 에 noIntro·cam·weather·time 이 없을 때) 또는 상단 '투어 시작' 버튼
  → 인트로 비행(기존 12초 경로)
  → 모달 「어떤 건물로 이동하시겠습니까?」  [하우스노웨어 성수] [하우스노웨어 몽골] [닫기]
  → 선택한 건물 정면까지 비행(상승 → 활공 → 정면 하강)
  → 성수: 모달 「입장하시겠습니까?」 [예] [아니오]
        예 → 실내 진입(§2.5)        아니오 → 자유 탐색(그 자리)
     몽골: 모달 「준비중입니다」 [확인] → 자유 탐색(그 자리)
```

- **끼어들기**: 인트로 비행 중 클릭·키 입력은 인트로만 건너뛰고 곧바로 건물 선택 모달로 간다(시나리오 유지). 건물 비행 중 입력은 무시한다(짧고 목적이 분명한 모션). `Esc` 는 언제든 시나리오 전체를 끝내고 자유 탐색으로 돌아간다(모달이 열려 있으면 모달을 닫는 것이 곧 시나리오 종료).
- **다시 열기**: 상단 바 `건물 이동` 버튼은 외관 자유 탐색 중 언제든 건물 선택 모달을 연다(인트로 없이 모달부터). `투어 시작` 은 인트로부터 다시 시작한다(기존 `인트로 비행` 버튼을 바꾼 것).
- **보행 시점 중 시작**: 시나리오가 시작되면 보행 시점은 해제된다(기존 인트로와 같음).
- 두 월드(성수 2041 · DS2 산악) 모두 같은 시나리오를 쓴다.

### 1.2 건물 정면 비행

- 접근 시점(카메라 위치 · 바라볼 점)은 월드 × 건물별로 `public/src/nowhere/tour-config.js` 에 둔다. 값은 건물 위치(`layout.buildings.*.pos/rotY`) 기준 상대 오프셋으로 정의하고, 화면을 보며 조정한다.
  - HAUS: 남측 전정(성수·DS2 모두 Blender y −31…−17, Three z +17…+31) 앞에서 포디움 입구를 바라본다.
  - FaceArch: 얼굴 정면(rotY 를 반영한 건물 정면 방향)에서 두 눈과 필로티를 함께 보는 구도.
- 비행 경로: 현재 위치 → 위로 `max(25 m, 직선거리 × 0.15)` 상승 → 두 점 사이 상공 → 접근점 상공 → 접근점. Catmull-Rom 곡선, 바라보는 점도 같은 비율로 보간. 시간 = `clamp(직선거리 / 40 m/s, 4 s, 8 s)`. 지면 고정(지면 + 1.2 m)은 그대로 적용된다.

### 1.3 모달

- 공용 `modal.js`: 제목 · 본문(선택) · 버튼 목록. 조작 안내 오버레이와 같은 패널 스타일. `Enter` = 기본 버튼, `Esc` = 닫기(시나리오 종료). 포커스는 기본 버튼, 모달이 떠 있는 동안 보행 마우스 고정은 해제한다.
- 건물 선택 모달의 각 선택지에는 한 줄 요약을 붙인다(성수: `assets/record.json` 의 규모·높이, 몽골: `assets/facearch.json` 의 높이).

### 1.4 분석 모드 제거

- 삭제: `public/src/nowhere/analysis.js`, 3개 HTML 의 `분석 모드` 버튼 · 레이어 필터 · 기록 카드 마크업, `nowhere.css` 의 분석 모드 · 카드 섹션, `main.js` 연결, `F` · `[` · `]` 단축키, 조작 안내 · README 의 해당 행.
- 남김: `layout.json` 의 `anchors`, `anchors.ko.json`(빌드 산출물, 웹에서 읽지 않음), 셰이더의 `uAnalysis` · `uScan*` 유니폼(값 0 고정, 화면 영향 없음 — 정리는 범위 밖).
- 테스트 `tests/nowhere-help.test.mjs`(b) 의 분석 모드 바인딩 검사는 새 바인딩(투어 · 엘리베이터)으로 바꾼다.

## 2. 성수 실내 뷰

### 2.1 에셋 분석 요약 (`public/assets/inner`)

- 모델은 모두 **Draco 압축 GLB**(WebP 텍스처). 웹 뷰어에는 Draco 디코더가 없으므로 Blender 로 불러와 meshopt 로 다시 내보낸다.
- 크기가 1~2 m 로 정규화되어 있어(예: 테이블 높이 0.48 m, 문 0.5~0.7 m) 실제 축척으로 다시 맞춘다. 원점은 바닥 중앙(min z = 0).
- 고폴리: `nail` · `sphinx` · `display` 각 약 20만, `office_building` 12.7만 삼각형 → 각 5만 이하로 줄인다.
- `env/modern_bathroom_1k.exr` 와 `light/light.exr`(4K, 21 MB)는 같은 HDRI 다. 웹에는 1K 만 `.hdr` 로 변환해 쓴다.
- `icons/home.svg` 는 실내 `밖으로 나가기` 버튼에 쓴다(`search` · `trophy` 는 이번 범위에서 쓰지 않는다).

### 2.2 층 구성과 배치

| 층 | 층고 · 평면 | 바닥 재질 | 배치(젠틀몬스터 매장식 대형 설치물, 괄호는 목표 크기) |
|---|---|---|---|
| **1F 로비** | 6 m, 포디움 둥근 사각 평면(약 34 × 34 m 전시 구역 + 뒤쪽 엘리베이터 코어) | `main/floor_*` 빨간 유약 타일 | 중앙 '성수 도시 모형': `office_building`(HAUS NOWHERE 미니어처, 높이 3 m) + `building_1~3`(그래피티 건물, 높이 1.4~1.9 m)을 큰 받침대 위에 배치 · `DJ`(2.4 m) · `display`(폭 6 m 대형 화면, §2.6) · 엘리베이터 문 `door_1`(높이 2.8 m) |
| **B1F 카페** | 4 m, 포디움 평면(약 26 × 26 m), 창 없음 | `b1f/floor_*` 보라 패브릭 | `table` 세트 6개(테이블 높이 0.75 m) · 버섯 몬스터 2개(손님, 1.2 m) |

- 공간 껍데기(바닥 · 벽 · 천장 · 창 · 기둥 · 엘리베이터 코어)는 HAUS NOWHERE 의 실루엣을 따른다. 포디움 층은 외관의 가로 띠창, 타워 층은 커튼월 유리. 벽 · 천장은 노출 콘크리트(외관 재질 톤).
- 모든 층에 엘리베이터 코어(문 `door_1` 2개)를 같은 평면 위치에 둔다(층 이동 시 같은 자리에서 나옴).

### 2.3 빌드 파이프라인

- `tools/nowhere/blender/inner_build.py`(+ 층 모듈): 껍데기 생성 → 에셋 가져오기(Draco) · 축척 · 배치 · 감축 → 층별 조명 · AO 굽기 → `build/nowhere/raw-inner/inner-{b1,1,12,13}.glb` + `public/assets/nowhere-inner/inner-layout.json` + 대표 렌더 `renders/inner-*.webp`.
- `package.json`: `nowhere:inner:build`, `nowhere:inner:optimize`(데스크톱 텍스처 1024, 모바일 512, meshopt — 외관과 같은 gltf-transform 설정).
- 원본 `public/assets/inner/` 는 그대로 둔다(빌드 입력).

      "exit": { "pos": [0, 0, 16], "radius": 2.0 },

- `entry` 는 외관에서 들어올 때(1F 만, 정문 쪽 남측), `spawn` 은 엘리베이터에서 내렸을 때(뒤쪽 북측 코어 앞), `exit` 는 1F 정문 출구 영역(반경 안에 들어가면 「밖으로 나가시겠습니까?」).

### 2.5 실내 진입 · 이동 · 나가기

- **진입**: 「입장하시겠습니까?」 예 → 화면을 0.6 초 동안 어둡게 → (첫 진입이면) 1F GLB 를 불러오며 진행률 표시 → 창밖 캡처 → 실내 씬으로 전환하고 0.6 초 동안 밝게. 1F `entry` 에서 보행 시점으로 시작한다.
- **렌더 전환**: 실내가 켜져 있는 동안 외관 씬은 그리지 않는다(`main.js` 렌더 루프가 활성 씬을 고른다). 후처리 · 기상 · 시간 컨트롤러는 그대로 쓴다.
- **조작**: 보행 시점(이동 · 달리기 · 점프 · 충돌 · 마우스 고정 그대로, 지면 높이 · 장애물 격자는 실내 메시로 새로 만든다). `V` 로 끄면 실내 궤도 카메라이며, 카메라는 층 `bounds` · 천장 안으로 제한된다(벽 밖으로 나가지 않음).
- **엘리베이터**: HUD 층 버튼(B1 · 1 · 12 · 13, 현재 층 강조) 또는 엘리베이터 문 반경 안에 들어가면 뜨는 「층 선택」 모달. 층 이동 = 0.4 초 어둡게 → 그 층 GLB(처음이면 불러오기) · 창밖 재캡처 → 그 층 `spawn`.
- **층 둘러보기**: HUD `이 층 둘러보기` → 그 층 `tour` 지점을 차례로 비행하며 하단에 설명 자막. 입력이 있으면 멈추고 그 자리에서 자유 이동.
- **나가기**: HUD `밖으로 나가기`(home 아이콘) 또는 1F `exit` 영역에서 뜨는 「밖으로 나가시겠습니까?」 [예] → 어둡게 → 외관 HAUS 접근 시점(카메라 시점) → 밝게.
- **실내에서 숨기는 UI**: 외관 카메라 프리셋 · 월드 전환 · `투어 시작` · `건물 이동`. 기상 · 시간 패널은 유지한다(창밖 캡처와 실내 조명에 반영).

### 2.6 조명 · 창밖 · 디스플레이

- 반사 환경: 욕실 HDRI 1K(`.hdr`)를 PMREM 으로. 층별 조명은 GLB 에 굽고(AO), 실시간 조명은 반구광 + 천장 방향광 1개.
- 창밖: 진입 · 층 이동 · 기상/시간 변경 완료 시, 외관 씬을 `CubeCamera`(256 px)로 HAUS 위치 · 그 층 `elevation` + 1.7 m 에서 캡처해 실내 씬 배경으로 쓴다(창 유리 너머로만 보임). 지하 B1F 는 캡처하지 않는다.
- 밤(`uNight` > 0.5): 실내 조명을 따뜻하게 키우고 창밖은 캡처된 밤 풍경.
- 1F `display` 화면: CanvasTexture 로 `HAUS NOWHERE SEOUL` · 현재 시각 · 기상 이름을 표시(1 분마다 갱신).

## 4. 오류 처리

- 실내 GLB · HDRI 불러오기 실패: 어둡게 했던 화면을 되돌리고 「실내를 불러오지 못했습니다」 모달 [다시 시도] [닫기], 외관 HAUS 정면에 머문다.
- 모달 중 창 크기 변경 · 탭 전환: 모달 유지, 시나리오 일시정지 없음(모달은 사용자 입력을 기다리는 상태).
- 시나리오 중 월드 전환 버튼: 시나리오를 끝내고 기존대로 페이지 이동.

## 5. 테스트 · 검증

- 단위(node:test):
  - `scenario` 단계 그래프: 모든 `next` 가 존재, 성수 → 예 → 실내 진입, 성수 → 아니오 → 자유, 몽골 → 확인 → 자유, `Esc` → 종료.
  - `flight`: 시작 · 끝 일치, 경로 최고점이 두 점보다 높음, 시간 4~8 초 범위.
  - `tour-config`: 두 월드 × 두 건물 접근 시점 존재 · 형식.
  - `inner-layout.json`: 4개 층, 파일 존재, `spawn` · `entry` · `exit` · `elevator` · `tour` 지점이 `bounds` 안, 예산(파일 크기).
  - 조작 안내: 새 바인딩(투어 건너뛰기 `Esc`, 실내 층 이동) 반영, 분석 모드 키 제거.
- 브라우저(playwriter): 두 월드에서 시나리오 전 구간, 몽골 준비중, 4개 층 이동 · 보행 충돌 · 층 둘러보기 · 나가기, 밤 · 비에서 창밖 캡처, 데스크톱 · 모바일 예산 실측.
